# Water and granular settling run as substeps per tick

A single falling-sand pass per tick lets only the bottom cell of each water column flow sideways — the cells above it just fall into the vacated spot. A poured column therefore kept standing as a pillar, shedding one cell per tick and spreading its base one cell per tick, for as many ticks as the column was tall. We decided the falling/flow pass (and the granular rubble/debris pass) runs `Constants.settleSubsteps` (6) times per tick, stopping early when a pass moves nothing.

**Why:** a pile that stands for seconds reads as a rendering artifact, not water; real water spread a dumped column almost immediately. Substeps keep the exact cell model (whole cells move, so the field never overshoots and the per-body head, erosion, jet, wash, and volume contracts are untouched) while raising the collapse rate to substeps-per-tick. The granular pass shares the substep count so a broken tower's rubble and the displaced water fall with one gravity instead of two.

**Consequences:** a settled field makes no moves and exits after the first pass, so at-rest cost is a single pass (the at-rest check also skips the momentum bounce/flap work); active flow costs up to `settleSubsteps` passes per tick, which is a few milliseconds on the 220×240 grid at 30 ticks/s. Rigid loose objects (furniture, lamps) keep moving at most one cell per tick — their motion is buoyancy displacement, not free fall. The substep count is a named constant, not a test-pinned default; the tests defend the observable contract (a poured column pancakes within a generous tick bound; falling rubble reaches the floor well within one-cell-per-tick time).
